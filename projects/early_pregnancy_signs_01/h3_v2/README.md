# V2：角色母版 → 每镜首帧 → H3 → 剪辑

本版按用户指定链路重新制作。旧版仅作内容和配音参考，不以程序人物动画冒充 H3 输出。当前状态：提示词已准备；等待用户生成角色母版与镜头首帧；尚未运行本集 H3。

## 你现在怎么生成

1. 将 `prompts/00_character_master.txt` 全文复制给 GPT-image2，生成角色母版。保存到 `references/character/character_master.png`。这是一个人的完整立绘，不是多人拼图。
2. 用母版生成 `prompts/00_character_sheet.txt`，保存为 `references/character/character_sheet.png`。这张设定表帮助检查一致性，不直接送进 H3。
3. 后面每生成一个镜头，都上传同一张 **character_master.png** 作为人物参考，再复制该镜头的 `prompts/shot_XX_image.txt` 全文。每次只生成一张独立画面，文件名和说明见 SHOT_LIST.md。
4. 先做 **01、03、05** 三张：检查片头的画风、坐姿和掩嘴动作。然后生成其余镜头。不要将已经变脸的镜头拿来作为下一个镜头的唯一参考。
5. PNG 原图，优先竖屏 9:16（如 1024×1792 或可用的最接近尺寸；1024×1792 实际不是精确 9:16，最终会安全裁切）。若工具支持精确 9:16，选 1080×1920。不需要手工写字幕、标题或数字。
6. 图片直接存入本目录即可，不必上传公共图床。完成后告诉我已放好；我会读图检查、同步 220 并执行 H3。若你放到别处，告诉我绝对路径。

建议优先生成母版和前三张样张，再继续批量，减少角色漂移导致的返工。人物母版和设定表共 2 张，镜头首帧 13 张，共 15 张；设定表可后补，不阻塞首镜试跑。

## 文件与职责

- `prompts/00_*.txt`：人物母版和设定表的 GPT-image2 提示词。
- `prompts/shot_XX_image.txt`：每镜独立、可直接复制的 GPT-image2 完整提示词。
- `prompts/shot_XX_h3.txt`：对应 H3 动作、镜头及稳定性要求草案。
- `shots.json`：镜头目的、画面构图、参考图路径、H3 提示词与时长目标。
- `references/character/`：用户生成的人物资产。
- `references/shots/`：用户生成的单镜首帧。
- `generated/h3/`：后续 H3 原片，当前为空。
- `review/`：后续参考图审核、首中尾抽帧、失败原因和选择记录。

## 生成与剪辑约定

优先 FL2VA 首帧图生视频。母版用于生成一致的首帧；H3 每次输入单镜首帧，不输入九宫格。先完成 01 号镜头的 5–8 秒试跑再批量，不把多个人物视图作为一张视频画面。

H3 提示词只安排一个主要动作和一种轻微运镜，不要求同一短片发生多个地点切换。保存 seed、模型/工作流、输入图 SHA256、原始 prompt、实际帧数和生成日志。模型具体可用分辨率、长度约束以服务器工作流实测为准，shots.json 的秒数是剪辑目标而非已验证 API 参数。

镜头 10–13 同样生成 H3 人物情境底片，清单、验孕时间线和医疗提示由 Remotion 叠加，避免模型画错医学文字。旁白统一后期配音，不要求人物口型，不使用 H3 自动生成的语音。最终以配音定剪辑长度；较长信息镜头可延长结尾静帧供阅读，不默认将短片大幅慢放。

必须检查：人物身份/衣着一致、成人观感、肢体与道具稳定、画面确实完成指定动作、无误导阳性结果、无遮挡关键图文。参考图不合格先修图；H3 动作不合格仅重做该镜。最终交付 MP4、封面、SRT、分镜、图片/视频提示词、来源与 QA。
