# Factory operating rules
Use 220 as primary host and /home/ly/shortvideo as the project root.
Local authoring root is /Users/ly/Desktop/project/shortvideo with the same Git layout. Original upstream repository is preserved at /Users/ly/Desktop/project/shortvideo-reference-original; treat it as a reference, never the production root. Put episode work in projects/<episode-id> and document selective reuse in library/ATTRIBUTIONS.md. Track source, prompts, manifests and QA summaries in Git; transfer media separately and record SHA256. Read docs/workspace-layout.md for sync rules.
Never store passwords/API keys in tracked files. Do not modify shared /home/video runtimes.
Read configs/resources.json and docs/workflow.md before production. Explicit user tool choices override defaults.
Do not claim capability is ready based solely on a path or HTTP response: distinguish configured, reachable, smoke-tested and production-approved.
All jobs write unique runs/<job-id>/ directories. Check GPU availability before model work. Never kill shared jobs.
A smoke test is not a validated style. Final content production requires script/storyboard, audio timing, preview review, render, QA and delivery manifest.

Python uses uv: orchestration via uv sync / uv run; TTS environment via uv venv. TTS borrows explicitly configured external dependency directories read-only. configs/tts-observed-packages.json is an observed snapshot, NOT a portable lockfile. A separate fully isolated TTS lock remains future work.

For 2D character scenario explainers (including cream storybook presets), read skills/2d-scenario-explainer/SKILL.md. First generate bounded character exploration (one single-character master and one design sheet) and discuss the actual images. After character direction is confirmed, prepare ALL complete shot reference frames with characters, backgrounds, props, action starting poses and text-safe space, plus per-shot Chinese narration, screen text, timing, action, camera and tool/model plan. Preserve scene continuity. If all frames are authorized, finish them without an extra three-sample approval gate. Present the complete numbered image-and-script package and record explicit version approval before TTS, H3, modeling, composition or rendering. Character approval and reference-image authorization are not video-production approval. Explicit user scope overrides defaults; never ask again for an already authorized step. Material changes require discussion again. Server connectivity failures must be reported immediately; never fall back to local video generation/composition/rendering. Episode media including review thumbnails and covers stay out of Git; track hashes and text manifests.

Style lookup: “奶油绘本科普” maps to styles/2d-handdrawn/cream-warm-storybook-list-explainer.json (v2) and skills/2d-scenario-explainer/references/cream-storybook.md. For caption/audio/layout revisions, read that skill’s references/captions-and-review.md before composition.

For any new video topic or continuation, start with skills/video-production/SKILL.md. Resolve current styles through styles/registry.json; use character-scenario for character methods, caption-alignment for subtitle/audio work, and video-qa for verification. Old 2d-scenario-explainer paths are compatibility redirects. Do not silently use the last episode as a series default.
