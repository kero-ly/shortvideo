# 字幕融合、声音与版本审阅

适用于各风格的合成与修订；视觉和排版取自本期锁定的layout与覆盖项。仅选择奶油绘本预设时参考character-scenario的cream-storybook规范。用户明确选择的排版优先。

## 同一条阅读线

先对原上方标题/说明、下方口播字幕与实际旁白做语义映射表：源文字 → 对应旁白 → 保留/合并/独立提示及理由 → 输出 cue ID。把上下字幕融合不能只删除上方文字。

把逐字或零碎 ASR 片段按完整短句合并，每 cue 保存 text、start、end、shot_id、source_indices、可选 context。编号/短主题标签与旁白放在同一个下方块；旁白本句已讲主题时省略重复标签。未口播但必须保留的事实明确标为补充提示，不伪装成逐字口播。不能为了精简去掉适用条件、否定词或关键行动建议。

全片固定主标题只说明主题，属于另一层级；不要同时在上方重复滚动每镜口播。提示语是否需要、具体文案由主题和用户决定，不把本期免责声明推广到所有主题。

## 真实音频驱动

1. 保存锁定文案、实际旁白音频哈希、分镜 start/frames 和 ASR/强制对齐来源。只有音频哈希一致且片段位置不变，才可复用旧词级时间；剪裁、重排、变速、重配后重新对齐受影响段落。
2. 使用词级时间定位句子边界；合并 cue 取对应首词开始至末词结束，并按自然停顿延长显示到下一句或镜头边界。不要按字符数均摊时间。短语不跨句断裂，长句按语义换行，停顿时避免字幕闪烁。
3. 校验全稿覆盖、每个源片段的去向、cue 顺序/重叠/遗漏、镜头边界和音轨长度。ASR同音错字不能替换已核实文案；可疑读音列入听审清单。
4. 逐镜源 WAV 必须完整落入时间槽。最后一个实际语音结束到视频结束默认至少0.6秒；不能用补静音掩盖已被截掉的旁白。复用 mix 前核对其长度、语音源与当前时间线，不能只看文案相同。
5. 配乐记录来源/授权、工具、版本、增益、淡入淡出与混音参数。轻快但不抢旁白；听审音乐可闻度、语音清晰度和句尾。例中程序合成配乐不能写成 Music3 生成。

## 看得见、听得到的审阅

前期 HTML 展示角色与全部完整参考帧、逐镜中文文案、动作/运镜和模型 prompt；图片可放大，编号可导航。制作批准记录到 PREPRODUCTION.md。

字幕/排版调整先在220输出代表静帧检查字号、颜色和遮挡，再输出完整带声低清样片检查连贯性。用户已明确要完整渲染时可直接执行。静帧不能替代动态与声音验收。样片网页提供视频、镜头跳转、逐句时间/文本与播放入口、SRT和对齐记录，方便用户指出具体秒数。

每次修订使用唯一 run 和明确 change summary；记录 source_review、本次改动及批准依据。用户说“改回前一版”时按实际版本记录恢复，不能猜样式；上下文不能确定时提供具体版本/缩略图选择。只改排版时保留已批准声轨和 cue，核对哈希/时间线不变，避免重跑图片、H3、TTS。

用户认可样片或明确要求完成后，在220渲染正式尺寸。复制该样片的 props、声轨与样式版本，避免旧 finalize 脚本恢复旧文案/信息卡。验收标题首尾可见、全部镜头布局、最长字幕、平台安全区与手机显示效果。

## QA 记录必须分层

- 自动技术：完整解码、帧数/帧率/尺寸、音轨时长、黑帧、响度、峰值、文件哈希。
- 自动字幕：全稿覆盖、语义映射、词级时间与边界、当前音频与对齐源一致性。
- 视觉抽样：具体镜头与采样时点，标题/字幕不裁切、不挡脸/动作；发现异常扩大检查。
- 完整播放/实际听审：记录是否完成、审阅者、问题及结论。未实际听审时保持 pending，技术通过不能写成“音画同步已完整验收”。

交付网页、MP4、封面、SRT、props、来源和 QA、SHA256 manifest。先校验下载文件哈希和网页媒体可加载，再交给用户。保留原生生成分辨率与最终合成分辨率的区别；媒体不入Git。
