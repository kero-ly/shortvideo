# 风格 skill 的端到端约定

风格 skill 以主题、受众、观点、事实来源、参考和可选工具要求作为输入。
1. 读取 brief，检查事实与素材来源；缺失关键事实时标注待核实。
2. 读取风格版本，确定时长、画幅、音色、镜头节奏与字幕安全区。
3. 先制作角色母版和设定图供看图确认；角色方向确认后，制作全部完整分镜参考帧（含背景、物品、动作起点及文字留白）与逐镜中文旁白、屏幕文字、时长、动作、运镜和工具路线。统一展示全部图文并确认版本后，才配音、H3、建模、剪辑和渲染。已授权全分镜时不在三镜样张后重复询问；用户指定范围或顺序优先。
4. 生成分段旁白，以真实音频时长编译时间线，不能随意压速凑时长。
5. 按镜头类型路由：信息图到Remotion；程序模拟到Godot；机械3D到Blender/FreeCAD；AI镜头到H3；参考图到图像工具。
6. 生成或选用有来源记录的配乐/音效，控制混音响度。
7. 合成低清样片，检查字幕、画面、口播同步；只重做失败阶段。
8. 正式渲染，执行技术QA和人工内容QA。
9. 交付视频、封面、字幕、来源/版本/参数清单、QA报告。

技能必须写清：前置条件、工具调用、输入输出、阶段依赖、失败恢复、预算和验收规则。用户指定工具优先。模板覆盖不了新内容时，应补镜头设计，不能只换文字强行套版。
已沉淀仓库 skill：skills/2d-scenario-explainer/SKILL.md（2D 手绘动画 · 暖色明亮低饱和 · 生活情境科普），基于首期内部审阅链路。它指导端到端制作，尚不是通用批量调度器；案例合成脚本仍需逐期适配。缓存依赖失效和自动事实审核尚未实现。

前期确认后记录批准版本；角色、分镜含义、关键事实或工具路线实质变更先讨论。220 连接异常立即通知，不擅自转到本地视频生产。媒体（含审核缩略图）不入 Git，仅追踪文本和哈希清单。


网页审阅是默认交付方式：把全分镜参考帧、逐镜中文旁白、屏幕文字、预计时长、动作/运镜及工具路线组织成可直接打开的HTML页面。提供镜头编号导航、点击放大原图和可折叠prompt，图片与文案一一对应；另存Markdown供归档。静态网页预览不等于视频渲染。先检查图像可加载与页面布局，再给用户审阅；记录用户批准的页面/图文包版本，不能因打开页面就推定批准。可参考 projects/early_pregnancy_signs_storybook_02/scripts/build_review.py，复制到新期时适配路径与主题。

已沉淀的合成优化：上下字幕按语义映射与去重融合，句级/词级时间取自实际旁白；复用声音核对哈希、时间线及结尾覆盖。排版先静帧检查，再完整带声样片；认可后正式尺寸渲染。自动技术QA、字幕检查、抽帧和实际听审分开记录。执行细节见 skills/2d-scenario-explainer/references/captions-and-review.md；奶油绘本最终排版见同目录cream-storybook.md及风格预设v2。
