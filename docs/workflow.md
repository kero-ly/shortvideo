# 风格 skill 的端到端约定

正式风格 skill 将以主题、受众、观点、事实来源、参考和可选工具要求作为输入。
1. 读取 brief，检查事实与素材来源；缺失关键事实时标注待核实。
2. 读取风格版本，确定时长、画幅、音色、镜头节奏与字幕安全区。
3. 提交完整角色母版/设定、脚本、逐镜呈现内容、动作运镜与工具/模型计划，先与用户讨论并明确确认版本，再开始素材与视频制作。仅需探索样张时取得限定范围的授权，展示后继续讨论。
4. 生成分段旁白，以真实音频时长编译时间线，不能随意压速凑时长。
5. 按镜头类型路由：信息图到Remotion；程序模拟到Godot；机械3D到Blender/FreeCAD；AI镜头到H3；参考图到图像工具。
6. 生成或选用有来源记录的配乐/音效，控制混音响度。
7. 合成低清样片，检查字幕、画面、口播同步；只重做失败阶段。
8. 正式渲染，执行技术QA和人工内容QA。
9. 交付视频、封面、字幕、来源/版本/参数清单、QA报告。

技能必须写清：前置条件、工具调用、输入输出、阶段依赖、失败恢复、预算和验收规则。用户指定工具优先。模板覆盖不了新内容时，应补镜头设计，不能只换文字强行套版。
已沉淀仓库 skill：skills/gentle-2d-scenario-explainer/SKILL.md（温柔陪伴 · 2D 情境科普），基于首期内部审阅链路。它指导端到端制作，尚不是通用批量调度器；案例合成脚本仍需逐期适配。缓存依赖失效和自动事实审核尚未实现。
